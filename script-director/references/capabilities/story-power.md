## I — 自述

故事不是"讲得更生动的案例"，它是**飞行模拟器**：让人在脑内跑一遍"遇到这种情况我该怎么做"，跑完之后人就带着脚本走了。

这决定了故事有硬结构要求，不是随便讲个事儿就算：

1. **必须先定想驱动的行为，再选情节。** 三种情节指向三种不同行为：
   - **挑战情节**（克服巨大障碍）→ "我能不能做到"（用于建立信心、推动攻坚）
   - **联系情节**（跨越分歧建立连接）→ "我们是不是一边的"（用于跨部门、客户关系、文化融合）
   - **创造情节**（用新办法解决老问题）→ "能不能换个做法"（用于创新、流程改造）
   先有行为，情节才有方向。反过来（讲个好故事再找用途）必然失败。
2. **必须具备"障碍 + 具体动作 + 结果"三段。** 缺障碍是流水账，缺动作无法模仿，缺结果没有说服力。
3. **不要替听众总结。** 把"所以我们要以客户为中心"这句删掉——总结会把脑内演练那一步抽掉，故事退化成信息。故事可以蕴藏理念，理念装不下故事。

一个高级用法是**跳板故事**：先讲一个让人自己产生"这不对吧"的故事，让疑问在听众脑中自己长出来，再给方案。它比直接给结论更能抵抗怀疑，因为结论是听众自己得出的。

## A1 — 书中案例

**英格索兰的"拖拉测试"（创造情节）**
- 问题：研发周期 4 年要压到 1 年，但团队习惯了漫长的强度测试。
- 做法：把塑料和金属样品绑在租来的车后保险杠上，在停车场拖着跑，直到警察来制止。
- 结果：证明塑料同样耐用，这个故事被命名为"拖拉测试"写进团队文件，隐喻变成"要数据，但要快得多"。

**贾里德的故事（挑战情节）**
- 问题：赛百味的健康定位缺乏说服力。
- 做法：讲一个大体重的人靠每天吃 SUBWAY 减掉大量体重的完整过程——障碍、动作、结果齐全。
- 结果：故事被反复传播，成为品牌最有效的资产，效果远超营养参数表。

**跳板故事：抵抗怀疑**
- 问题：直接给结论会被反驳。
- 做法：先讲一个让人自己觉得"这说不通"的短故事。
- 结果：疑问由听众自己产生，方案落地时不再需要辩论。

## A2 — 未来触发

**用户会在这些情境下需要它**
1. 要传递一种"遇到情况该怎么办"的判断，讲规定没人听。
2. 培训/带新人/文化宣导，希望对方能自己处理新情况。
3. 有一堆素材，想把它们组织成能打动人的一段。
4. 要回应质疑，直接讲道理会吵起来。

**语言信号**
- 中文：`讲个故事` `怎么讲故事` `案例怎么讲` `培训没人听` `怎么让新人学会判断` `文化怎么落地` `怎么举例才有说服力` `故事讲完没反应` `想做个开场故事`
- 英文：`tell a story` `storytelling` `case study` `narrative` `how to make this stick` `parable` `anecdote`

**与相邻能力的区分（初稿）**
- 与 `emotional-appeal`：故事顺带产生情感，但它的独特产出是**行动脚本**。如果用户只问"怎么让人在乎"，用情感；问"怎么让人知道该怎么做"，用故事。
- 与 `concretize`：具体化产出画面，故事产出序列。画面能被看见，序列能被演练。
- 与 `simulate-experience`：故事是**用别人的经历**做模拟，模拟体验是**让自己/团队亲自跑一遍**。前者成本低、可规模化；后者迁移率高。

## E — 执行步骤

1. **定行为**：写出"听完之后，我希望他遇到什么情况时做什么"。完成标准：一个具体动作 + 一个触发情境。
2. **选情节**：按行为匹配——
   - 需要攻坚/信心 → 挑战情节
   - 需要协作/认同 → 联系情节
   - 需要改变做法 → 创造情节
   完成标准：能一句话说明"为什么这个情节能驱动这个行为"。
3. **补三段**：障碍（越具体越可信）、动作（可被模仿的关键一步）、结果（可验证，不要形容词）。完成标准：三段齐备，且动作能被别人照做。
   - 判停点：若找不到真实案例，不要编——转 `simulate-experience` 做现场演练，或转 `concretize` 用假设情境，并明确标注是假设。
4. **删总结**：去掉结尾的道德句、去掉"这说明……"。完成标准：故事在结果处结束。
5. **演练测试**：讲给一个不知情的人，隔一天问他"如果遇到 X 你会怎么做"。完成标准：他的回答接近你第 1 步写的行为。

## B — 边界

**不要用**
- 需要精确传达参数、流程、合规要求的场合——故事的歧义会被放大。
- 时间极紧的通报（故障、危机）：此时要的是指令，不是叙事。
- 故事与核心无关时：一个好玩但跑题的故事会把核心挤掉（这是最常见的失败）。

**书中警告的失败模式**
- 故事不反映核心 → 换个故事（见 `p20`）。
- 从省略故事直接跳到"要诀"：把演练抽掉了（见 `p23`）。
- 用理念去装故事：理念装不下故事，只能反过来（见 `p24`）。
- 把故事当娱乐：讲完只有"挺有意思"（见 `ce13`）。

**容易混淆**
- ≠ 案例（案例给信息，故事给脚本）
- ≠ 段子（段子给情绪，故事给应对方案）
- 与 `simulate-experience` 的分界：**用别人的经历** → 故事；**自己跑一遍** → 模拟体验。

**作者盲点（阶段 0 批判）**
本书对故事的推荐几乎无条件，但故事有**选择性偏差**问题：能被讲好的故事往往是异常值（英雄个案），用它推导普遍做法会误导。使用时需提示：故事负责驱动行为，不负责证明概率——涉及概率判断时必须另配数据（但要分段，见 `p19`）。

## 相关能力

- 依赖：`core-message`（故事必须服务核心）
- 组合：`emotional-appeal`（故事是最强的情感载体）、`simulate-experience`（讲完再演练，迁移率最高）
- 对比：`concretize`（画面 vs 序列）
