# 内容资产：保存机制，也保存边界

## 目录与写入

优先使用用户指定资产系统。没有约定时，完整策划或明确建库任务在当前项目建立：

```text
outputs/<项目标识>/<脚本ID>-v01.md
outputs/<项目标识>/<脚本ID>-v01.html
content-assets/<品牌标识>/records/<资产ID>/v0001.json
content-assets/<品牌标识>/records/<资产ID>/v0002.json
```

这是新库可选的结构化格式，使用下文脚本保存；已有 Markdown 或其他格式的库继续沿用，不重复建第二套真相。按需创建，不生成空库。品牌不明时用项目标识，不合并不同品牌的产品事实。已有同名文件先读；脚本改稿新建版本，事实修订和机制更新记录来源、日期与修订原因。结构化库索引由版本记录即时计算，无需维护易过期的第二份索引；其他格式的库保存后同步其现有索引。

MD与HTML是面向使用者的默认交付；JSON是内部记录，不能取代这两种文件。HTML由同版MD生成，记录中可用`content.deliverables`保存两者项目相对路径。修改脚本后同步重生成HTML，旧版保留。完整制作规范见 [交付模板](deliverables.md)。

索引至少含：ID、类型、名称、标签、状态、版本或更新日期、相对路径。标签围绕品牌/品类/人群处境/购买障碍/机制/渠道，避免只用“爆款”“好脚本”。

## 三种资产不能混淆

脚本本身另存为 `script` 类型（SCR），包含方向、概念、时间线和本次引用版本；下面三种知识资产与脚本关联。来源素材、角色设定、品牌创作原则、系列规则可放在机制卡的 content 扩展字段中；确有规模时按用户约定独立建库，不预先铺空目录。

### 事实卡 FACT

字段：ID、品牌与 SKU、准确主张、来源文件/URL/用户提供信息及日期、适用条件、证据局限、核验状态、更新时间、关联脚本。

状态：`用户提供但未独立核验 / 有来源支持 / 已过期 / 被更正`。价格与活动写有效期；不知道时写“未知”，复用前重新确认。用户说过不等于已独立验证。安全用法和功效主张不能从相似 SKU 迁移。

### 机制卡 PAT

字段：ID、名称、内容方向（展示/种草/口播/搞怪等）、表现风格、创意机制、最强画面或包袱、来源及原作链接/文件、抽象结构、适合的观看动机或购买障碍、必要事实与资源、不适用条件、关联脚本及版本、验证状态、下一次测试问题。

状态：`待验证 / 有观察支持 / 多次观察支持 / 条件失效`。抽象可迁移的冲突、证明形式、叙事视角；不要把别人的台词、角色和品牌记忆点整体搬过来。参考视频不可访问时，只基于用户提供的信息分析，注明范围。

### 复盘卡 REV

字段：ID、脚本 ID/版本、素材 ID、渠道、上线时间、观察窗口、目标、指标值和定义、样本量、数据来源、对照条件、评论原文及来源、观察、解释假设、限制、下一轮变化、关联事实/机制。

未提供的数据标“未提供”，不补零。客户隐私在复盘中做必要匿名化。

## 调用与更新

1. 先按购买障碍与场景检索，再看品类和机制；优先找适用条件匹配的资产，而非仅看播放量。
2. 复用前检查 SKU、价格活动、证据有效期、演员/场景条件。脚本注明沿用了什么、改了什么、为什么仍适用。
3. 旧事实失效时保留历史版本含义，将当前卡标为过期或更正，指出受影响脚本；不悄悄改写历史。
4. 新观察与旧结论矛盾时，记录矛盾并收窄适用条件；不只保留成功案例。

## 上线复盘

把“发生了什么”与“可能为什么”分开。例如：开头流失较高是观察；“观众不喜欢人物”是待验证解释。播放、停留、点击、成交是不同环节，不能互相替代。

比较素材需记录观察窗口、曝光样本、时长、人群、渠道、预算和优惠差异等可得条件；不可比时不宣称创意导致结果。可提出内容层面的对照版本，投放执行不在本技能范围。

没有受控验证时只记录相关观察；不要给“多次支持”设一个无依据的普适播放阈值。每次迭代尽量只改变一个主要创意变量，并说明预期影响哪个环节。

没有上线数据也能沉淀：把逻辑、素材需求、拍摄失败原因和待测试问题保存为待验证资产。已拍摄不代表已验证，拍不出来本身也值得记录。

## 创意资产的最小可迁移单元

保存“为什么成立”：内容方向、观看动机、主机制、最强场面、铺垫与回收关系、商品接入位置、可替换槽位、必要条件与不能替换的部分。保留一个没做好的版本及失败原因，避免库里全是主观精选。

例：不是存“支架辞职很好笑”，而是存“把商品真实形态变化解释为角色愿望的实现：职场拟人→认真协商→实际折叠完成躺平回收；适合有明显状态变化的物件，不适合需要复杂功能解释或品牌不接受拟人的任务”。跨品牌只迁移这种抽象机制，事实和品牌私人素材仍隔离。

## 本地工具：asset_store.py

Python 3.10+，仅标准库。以下路径中的 `<技能目录>` 替换为当前技能实际位置，命令在用户项目执行，root 指向该项目资产目录。用文件编辑工具创建输入 JSON，再运行命令，不在命令行中拼接大段脚本或敏感数据。

```sh
python3 <技能目录>/scripts/asset_store.py --root ./content-assets add --input ./record.json
python3 <技能目录>/scripts/asset_store.py --root ./content-assets search --brand demo --kind pattern --query 拟人
python3 <技能目录>/scripts/asset_store.py --root ./content-assets search --brand demo --tag 搞怪
python3 <技能目录>/scripts/asset_store.py --root ./content-assets index --brand demo
python3 <技能目录>/scripts/asset_store.py --root ./content-assets check
```

`add` 自动为同品牌同 ID 创建新版本，不覆盖旧版本；并发写入冲突返回错误，重新读取后再保存。`search` 返回最新版本，`index` 输出派生索引且不写文件，`check` 检查全部历史记录、镜头时间和同品牌引用。查询不存在的库返回空结果，不创建目录。脚本不访问网络，不发布内容。

输入公共字段：`id, brand, kind, title, status, tags, sources, links, content`。id/brand 用字母、数字、中文、下划线、连字符；kind 为 `fact/pattern/script/review`。tags、sources、links 是字符串列表；sources 保留来源与日期，links 为同品牌资产 ID。保存顺序通常是事实→脚本→机制卡；复盘以后新增，再保存机制新版本。新脚本要引用机制时可用已有机制版本，不做双向循环依赖。

| kind | status 可选值 | content 的必填字段 |
|---|---|---|
| fact | 用户提供但未独立核验 / 有来源支持 / 已过期 / 被更正 | claim, scope；sources 非空 |
| pattern | 待验证 / 有观察支持 / 多次观察支持 / 条件失效 | mechanism, applies_when, avoid_when, memorable_moment |
| script | 方案完成；兼容旧创意草案 / 待核实 / 可拍摄稿 | direction, concept, target_duration, shots；新版完成记录另需三个角色的内容定位 |
| review | 待补数据 / 观察记录 / 可比较记录 | observations, hypotheses, limitations, next_test |

`content` 可扩展保存本文前面定义的字段，例如 SKU、有效期、时间窗口、指标与样本量。`used_assets` 用 `[{"id":"FACT-001","version":1}]` 锁定实际引用版本；links 用于导航，不锁版本。`revision_reason` 记录修订理由。不要只存必填项就丢掉任务需要的证据。

新版完整方案记录用`status:方案完成`、`content.plan_model:preproduction-three-role-v1`，`plan_sections`含planning、research、writing三项非空内容或文件定位，`verification_summary`说明核查范围和未决项。`critical_inputs_missing`非空不能标完成。无需production_readiness、拍摄排期或导出配置，不能把后续制作条件误作前期交付完成条件。旧八部分记录兼容保留，不自动迁移或升级。工具仅检查结构，不证明策略质量、事实真实或素材已获授权，三角色内容仍须人工核对。

每镜 `start/end` 为秒，`visual` 为画面；可补 dialogue、subtitle、audio、purpose、fact_ids。时间从0开始、连续无重叠且结束与target_duration相符。`unresolved` 为非空时不能保存为可拍摄稿。有观察支持的机制必须关联复盘 ID，但脚本不判断该复盘质量，人工仍须核查，不能据校验通过升级结论。

可复制 [示例记录](../assets/script-record.example.json) 改写；示例是虚构练习，没有实际商品或上线结果。若脚本返回错误，处理原因并再次校验；不声称已保存。这个工具不生成创意，不检测事实真伪，也不替代人工导演判断。
