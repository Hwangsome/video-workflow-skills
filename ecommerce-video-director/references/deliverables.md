# 脚本交付模板

按用户任务裁剪，不为了填表编造信息。

## 拍摄稿

```markdown
# <商品 / 项目> · <创意名>
脚本 ID：SCR-<项目>-001 ｜ 版本：v01 ｜ 状态：创意草案 / 待核实 / 可拍摄稿

## 策划依据
- 渠道、时长、目标动作：
- 观众处境 / 购买障碍：
- 核心购买理由 / 支撑事实：
- 最小商品依据：具体特点 → 使用场景 → 可见动作 → 来源与限制：
- 事实来源与资产引用（ID + 版本）：
- 本次创意机制及选择原因：
- 内容方向 / 表现风格 / 最强一幕：
- 观众想继续看的问题或体验 / 在哪镜兑现：
- 资源限制与采用的假设：
- 待核实事项（影响哪句 / 哪镜）：

## 分镜
| 镜号 | 起止时间 | 主体、景别与动作 | 口播 / 对白 | 屏幕文字 | 声音 / 剪辑 | 镜头目的 / 证据 ID |
|---|---|---|---|---|---|---|

## 拍摄执行
- 人员、场地、产品与道具：
- 必拍关键镜、可删镜与低成本替代：
- 演示步骤、控制条件、结果边界与原始记录要求：
- 台词朗读估时、动作留时、总时长核对：
- 表演目的、停顿与反应 / 关键声画设计：
- 连续性与场景集中拍摄顺序（需要时）：

## 自检与验证
- 开头承诺在哪镜兑现：
- 商品参与因果链的位置：
- 希望观众记住的商品特点/品牌线索与对应镜号（作者预期，非测试结论）：
- 对目标观众的选择理由；与最近创意的实质差异：
- 每项事实或效果结论的来源：
- 主要问题、处理方式与稿件状态：
- 下一版要检验什么 / 建议只改变什么：
```

时间段连续且总时长与 brief 相符。一个镜头可跨多个剪辑点，不以固定镜数取代节奏判断。屏幕字幕不必重复整段口播；保留必须被准确理解的限制条件。

## 局部改稿

交付“原句或原镜 → 修改版 → 修改目的”，必要时说明对后续镜头的影响。用户只要三个开场，就给三个可执行开场及各自兑现方式，不顺带重写整片。

## 交付说明

完整脚本默认交付同名、同版的Markdown与HTML，JSON仅为可选的内部检索记录，不能代替用户可读交付。

1. 先完成并审查Markdown，以它为内容事实源。
2. 按脚本逻辑生成HTML：开头交代标题、时长、版本、状态与创意；分镜严格按时间顺序逐卡展开，镜号与时间明显，动作、对白、字幕/声音分区；执行与替代拍法、待确认事实及验证记录放在后部。创意需要保留的停顿、揭示和回扣，必须连同原稿文字保留，不为美化擅自改写或删掉。
3. 页面为自包含单文件，不依赖CDN、远程字体、外部样式或图片；适配手机与桌面，中文易读。打印时隐藏操作按钮，镜头卡片避免跨页断开。风格服务脚本的阅读节奏，不用装饰压过关键动作与台词。
4. 核对MD与HTML的标题、版本、镜数、时间、对白、状态一致。实际打开HTML检查桌面和窄屏，确认无水平溢出、文字截断或卡片内容丢失。没有浏览器条件时报告未完成视觉检查，不能宣称预览通过。

基础阅读页可用随包工具生成（Python 3.10+，标准库）：

```bash
python3 <技能目录>/scripts/render_script.py <项目目录>/脚本-v01.md
```

默认输出同目录同名`.html`。源MD用`#`标题、`##`章节、`-`列表与管道分镜表；表头需有“镜”及“画面”，对白列包含“对白/口播/台词”。支持粗体、行内代码和普通链接，原始HTML会转义；不假装支持全部Markdown方言。复杂嵌套、代码围栏等超出子集时先将稿件整理为受支持结构，并核对内容，或另行制作HTML，不能静默丢内容。

默认阅读页采用纸色与深蓝、目录导航、分镜卡片、只看分镜切换和打印样式。可以根据内容定制布局或视觉强调，但MD仍为事实源，修改内容要先改MD再重生成。已有HTML不自动覆盖；确认该HTML是派生产物且没有独立改稿后可用`--overwrite`，否则另存新版本。直接手改HTML的内容应回写MD；不维护两份互相矛盾的稿。

保存后返回两个实际文件链接、版本、状态与未决事实。完整脚本与资产记录共用ID；检查文件实际存在，不把聊天中的文字或未生成的预期路径称作交付完成。

## 多方向交付

用户要方向：给带编号的方向比较表（方向、创意名、一句话设定、最强画面、商品角色、制作难度），每项给3—5个关键动作。从零只说“写一个脚本”且方向未定时，同样先给选项，附推荐与选择邀请后结束本轮；已选、已指定方向或授权代选才进入完整稿。见 [方向选择能力卡](direction-selection.md)。

用户只选多个编号或风格时，默认融合成一条脚本。交付时先说明各风格的作用，再给一个标题、一条时间线和一个结尾。不要交两条独立成片，不将两个完整故事机械拼接。

只有明确要求“每种一条”“分别成片”“两条独立脚本”或要求把各选项分别展开时，才交各自时间线、台词与制作要点。原任务已有多稿数量约定时沿用。单纯“多给几个脚本”但类型与点子未定时先给可选概念，选定范围后再展开。多稿共用brief与事实表，每条保留完整过程。

## 审稿与复盘交付

审稿使用“保留项→证据位置→问题→具体替代→稿件状态”；复盘使用“事实观察→原因假设→混淆变量→下一版测试→资产更新”。用户没有提供成片时只能审脚本，不能声称完成了审片。

## 代表案例记录

公开合成演练或经授权脱敏的案例按 [examples规范](../examples/README.md) 保存。记录输入与资料状态、候选、选择来源、完整输出、商品记忆检查、改进项和验证范围。任务资料与实际输出都留下，不能只存最终好看的稿件。普通项目不自动上传到示例库。
