## 新记录的格式

新增案例采用以下字段，按需填写，不编造缺失事实：

1. **基本信息**：ID、日期、版本、作者/执行环境可得信息、记录性质（合成演练/授权真实案例）、分享授权和隐私处理。
2. **任务输入**：用户原始需求或固定测试提示、商品资料、目标、资源限制；区分事实、假设、待核实内容。
3. **创意候选**：编号、机制、首屏、过程、记忆点、商品关联和难度；记录推荐理由。
4. **选择过程**：用户实际选了什么，或演练指定什么；未选不能补写成用户已选。
5. **实际输出**：完整时间线、台词、声画、执行说明；能关联对应脚本版本。
6. **评审与修改**：商品记忆、选择理由、差异性、事实边界、拍摄可行性；问题具体到镜号，保留未解决项。
7. **验证范围**：文本检查、真人朗读、试拍、观众复述、上线数据分别记录实际完成情况；未做写未做。
8. **资产抽象**：可迁移机制、适用/不适用条件、下一次问题；没有效果证据保持待验证。

真实品牌记录须获得公开分享授权并脱敏。普通交付继续保存在用户项目，不自动进入本目录或GitHub。没有授权时可以抽象成明确标注的合成演练，但不能冒充原客户真实效果。

## 如何使用示例

先做自己的商品依据和候选，再在需要时读一条示例，检查其约束能否迁移。例如服饰的站坐动作可借鉴到使用状态对比，不能把“两端开合”的结构移植给普通拉链。食品的声音编排也不能推导任何健康功效。

新增示例后更新索引；发生实测反馈时另存版本和证据，不悄悄将旧演练改成成功案例。每个公开案例仍需人工核验授权、事实与结论，目录存在不代表通过实测。
