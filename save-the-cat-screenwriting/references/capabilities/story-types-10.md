## R — Reading(原文)

> "如果你的剧本可以被归入到'公路电影',那么你必须知道我命名为'金羊毛'的类型……使故事成功的不是事件本身,而是主角从那些事件中对自我的认识。"——第一本 第二章「似而不同」

> "《雨人》怎么算?是'金羊毛'型还是'伙伴之情'型?(答案是'伙伴之情'。)"——第一本 第二章 总结

出处:第一本 L916–1304;第二本 10 章各类型子类型表(全书)。

## I — Interpretation(自述)

作者的判断很硬:**你不可能给出一个在经典故事里找不到影子的创意**。所以第一步不是"我要写得多新",而是"它属于哪台引擎"。类型不是体裁(喜剧/动作),而是**故事赖以运转的底层机制**,每台引擎都有自己的硬规则,遵守规则才有"似而不同"的空间。

十种引擎及各自不可破的规则:

| 类型 | 构成 | 硬规则 |
|---|---|---|
| **鬼怪屋** Monster in the House | 怪物 + 密闭空间 + 原罪 | 空间必须有边界(逃不掉);怪物须超自然或有压倒性;要有贪婪/罪招来怪物;原罪者受罚、悔改者得活 |
| **金羊毛** Golden Fleece | 上路 + 找东西 | 事件本身不重要,重要的是每个事件如何改变主角;终点发现的常是自我 |
| **如愿以偿** Out of the Bottle | 魔法/诅咒 + 一个愿望 | 主角须是被压迫的小人物;魔法必须失效,主角学到"魔法不是万能";诅咒型则反向:先给好处、终须付代价 |
| **麻烦家伙** Dude with a Problem | 普通人 + 巨灾 | 主角越普通、坏蛋越强,效果越好;主角必须用尽办法 |
| **变迁仪式** Rites of Passage | 生活阶段的痛苦转变 | 攻击主角的是无形之力(成瘾/中年/丧失);旁人都在"开玩笑",只有亲历者懂;结局是屈服而非战胜 |
| **伙伴之情** Buddy Love | 两个不完整的人 | 本质是伪装的爱情故事:起初互厌→发现离不开→分离/争斗(一无所有)→放下自尊 |
| **推理侦探** Whydunit | 秘密 + 调查者 | 重点不是"谁",是"为什么";观众是真正的侦探;结局必须让人对人性本身震惊 |
| **愚者成功** Fool Triumphant | 被低估者 + 权势集团 | 愚者须被反复证明"不可能成功";须有一个看笑话的知情者;权势集团最后自取其辱 |
| **被制度化** Institutionalized | 群体/组织/家庭 | 既致敬组织又暴露丧失个性;通常用外来者视角带观众进入;终问"我和他们比谁更疯" |
| **超级英雄** Superhero | 非凡者 + 平凡世界 | 必须给优势同时给痛苦(被误解/孤独);一旦观众接受其能力,必须重新给他同情 |

判别动作:把创意压成一句话 → 逐条比对构成要素 → 归入最贴切的一类(可允许跨两类,但要选主引擎)→ 直接获得该类型的**必备桥段清单与常见失败点**。

## A1 — Past Application(书中案例)

- **《小魔煞》**:作者点名的失败案例。怪物(蜘蛛)不可怕、没有真正的"屋子"(居民随时可以走),违反鬼怪屋两条硬规则,结果类型混杂、张力消失。
- **《雨人》判定**:看起来像公路片(金羊毛),作者判定是"伙伴之情"——因为故事的核心是两人关系而非旅程中的自我发现;并指出主角(汤姆·克鲁斯)承担全部转变,伙伴(达斯汀·霍夫曼)是催化剂。
- **《早餐俱乐部》/《超级名模》判定**:前者是"被制度化"(不是变迁仪式),后者是"超级英雄"典型——作者用这类"反直觉归类"证明类型判的是机制不是题材。
- **第二本的系统化**:10 章、每章 5 部影片、每型再分子类型(如鬼怪屋分家庭怪物/连环杀手/超自然/虚无型),把每种引擎的变体表列了出来。

## A2 — Future Trigger(触发条件)

**用户情境**
1. 创意已有一句话,但"不知道往哪个方向写才不落俗套"。
2. 写出来的东西"像很多片但又都不像",需要找到对标坐标系。
3. 要给内容/品牌故事定型,以便复制成功模式。
4. 判断一个竞品/爆款"为什么能成",需要拆它的引擎。

**语言信号**
- "这算什么类型 / 这是不是 XX 片的翻版 / 有没有类似的片子"
- "我这个故事像什么 / 对标哪个 / 怎么做出差异化"
- "story type / genre / 套路 / 类型片"
- "为什么这部能火"

**与相邻能力的区分(定稿)**
- 用户要**验证一句话是否成立** → `logline-validation`;本卡假设一句话已成立。
- 用户要**排结构** → `beat-sheet-bs2`;类型决定"必备桥段",节拍表决定"位置"。
- 用户要**设计主角/坏蛋** → `protagonist-antagonist`;类型只给角色功能位。

## E — Execution(可执行步骤)

1. **压成一句话**,并写下 3 个"最像的已有作品"。完成标准:3 个对标都能说出"像在哪一点"。
2. **逐型比对构成要素**。用十型的"构成"列过一遍,标出命中的类型(允许 1–2 个)。完成标准:给出主引擎 + 次引擎,并说明为什么不是另一个候选。
3. **调取硬规则清单**。列出该类型的 3–5 条硬规则。完成标准:每条都能对应到"我这个故事里哪个设定在执行它"。
4. **找违规点**。逐条问"我有没有违反?"——违反的要么改设定,要么明确说明为什么这里可以破(破规则必须支付代价:用更强的其他元素补偿)。
5. **出差异化方案**。在该类型内找"没有被用过的纠葛":换空间、换原罪、换代价、换视角。完成标准:给出 3 个"似而不同"的具体改动,每个改动都能说出它动了哪条规则。
6. **输出**:主类型 + 硬规则对照表(规则/我的执行/是否违规)+ 3 个差异化改动 + 该类型的 3 部必看对标。

## B — Boundary(边界)

- **只是起点,不是分类学**:作者自承"找例外你就误解了本章"。别为一部跨类型的作品争论归属,选最能指导写作的主引擎即可。
- **不适用于反类型/元叙事作品**:故意混类型、拆类型的作品(如《林中小屋》)需要另一套分析框架。
- **第二本的具体片例有年代局限**:子类型表基于 2005 年前的市场;流媒体时代的类型融合更快,子类型需自行扩充。
- **与"体裁标签"的混淆**:用户说"我这是悬疑片"时,不要直接当作类型判定——要问机制(是"为什么干"还是"别被吃掉")。

## 相关能力

- **组合** `logline-validation`:类型判定常反过来修正一句话里的"意外"设计。
- **组合** `golden-rules`:类型硬规则与八条红线常重叠(如鬼怪屋的"空间必须有边界"与"单一魔力")。
