# 救猫咪三部曲(电影编剧宝典 / 经典电影剧本探秘 / 反击战!) — 全书能力入口

## 触发与不触发

**适用**：与本书能力域相关的咨询与任务（见下方路由表的意图列）。
**不适用**：
- 纯技术文档、API 文档、合规披露的中性文本写作
- 作品的艺术价值判断、美学批评、影史定位
- 版权、经纪、合同等法律与商业谈判
- 与叙事无关的代码、数据、运营任务

## 核心原则（常驻速览，概览类问题读到这里即可回答）

1. 先验证一句话,再动结构——说不清"讲什么"就是故事还没想清楚。
2. 每条叙事都是某台类型引擎;先懂硬规则,才有"似而不同"。
3. 主角要被观众愿意跟随(救猫咪),动机要能还原到生存/饥饿/性/护所爱/惧死亡。
4. 结构可量化:15 个节拍托住三幕,40 张场景卡托住每段;每卡必须有情绪翻转与冲突。
5. 坏蛋要稍强于主角且与之镜像;除坏蛋外所有人必须改变。
6. 诊断优先于灵感:病有名字(枝蔓/半步/模糊),有清单,有处方。
7. 规则可破,但要付代价——懂了才破,不懂就守。

## 边界与判停

- 用户只想查书中名词 → 读术语词典即可,不加载能力卡。
- 用户要求"保证卖座/保证爆款" → 明确拒绝承诺,只能提高结构合格率。
- 用户的项目是反结构/实验性创作 → 先确认意图,不要强行套节拍表。
- 讨论已超出叙事范围(如法律、投资) → 说明边界并停止。
