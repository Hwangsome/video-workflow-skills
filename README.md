# 电商短视频编导 / 脚本策划

把商品资料变成有创意、能拍摄的短视频，让每次创作留下可复用的资产。

`ecommerce-video-director` 是一个面向电商内容工作的 Agent Skill。它帮助你寻找产品展示、生活种草、人物口播、搞怪离谱、剧情反转等创意，选定后展开分镜、台词和拍摄说明，并在交付和复盘中整理事实、脚本与创意机制。

**先看点子，再选方向，最后拿到能执行的脚本。**

[快速开始](#快速开始) · [创意方向](#同一商品可以拍成什么) · [工作流程](#它怎么工作) · [资产沉淀](#怎样沉淀资产) · [技能入口](ecommerce-video-director/SKILL.md)

## 为什么做这个技能

电商短视频创作经常卡在几件事上：商品资料很全，却不知道拍什么；想要不同风格，拿到的却是换了开头的同一个广告；脚本读起来顺，到了现场才发现动作、时间和资源对不上。

另一个问题是积累。写过的稿子散落在聊天记录里，参考视频只留下链接，上一条哪里有效、哪里失败，也很难被下一次创作调用。

这个技能把创意选择、脚本执行和资产复用连在一起。商品可以成为故事里的解法、角色、冲突起因或视觉符号，让观众记住的不只是一个与产品无关的段子。

## 快速开始

### 方式一：复制提示词，让 Agent 安装

如果你使用的 Agent 支持访问 GitHub、读写本地文件和安装技能，可以直接把下面整段发送给它：

```text
请帮我安装这个仓库中的电商短视频编导技能：
https://github.com/Hwangsome/video-workflow-skills

需要安装的技能名称：ecommerce-video-director
仓库内的技能路径：ecommerce-video-director/

请先读取仓库 README 和该目录下的 SKILL.md，再按当前 Agent
实际支持的技能安装方式，安装完整的 ecommerce-video-director 文件夹，
保留 references/、scripts/、assets/、examples/ 和 evals/，不要只复制 SKILL.md。

如果已有同名技能，请先比较版本、保留本地修改，再处理更新。
安装后检查入口与相对引用是否可访问，告诉我实际安装位置、
调用方法，以及是否需要刷新技能列表或开启新会话。
如果当前环境不支持安装，请说明限制并给出可行的手动加载方式，
不要把仅下载仓库当成安装完成。
```

这段提示词用于安装技能，不会自动开始某个商品的策划。安装位置由宿主工具的实际约定决定；普通聊天环境如果没有文件或技能加载能力，不能只靠一个仓库链接完成安装。

### 方式二：手动获取完整技能

```bash
gh repo clone Hwangsome/video-workflow-skills
cd video-workflow-skills
```

没有 GitHub CLI 时，可以使用 `git clone https://github.com/Hwangsome/video-workflow-skills.git`。

将完整的 [`ecommerce-video-director/`](ecommerce-video-director/) 文件夹放到你所用工具支持的技能目录，或让能够读取本地文件的 Agent 按其中的 [`SKILL.md`](ecommerce-video-director/SKILL.md) 执行。具体加载方式以宿主工具为准。

保留整个文件夹：入口会按任务读取 `references/`。普通脚本策划不需要额外安装 Python 包；运行本地资产工具需要 Python 3.10+，仅使用标准库。

### 安装后，复制这段开始使用

```text
使用 ecommerce-video-director，给一次性马桶刷策划短视频。
先给我不同的创意方向，我选定后再写完整脚本。
```

方向未定时，技能默认先提供五类具体创意。每项包含编号、创意名、第一画面与首句、关键过程、记忆点、商品关联和制作难度，并给出推荐理由。它会在这里停下来，让你选择。

你可以接着说：

```text
选E，写成35秒，双人、手机拍摄。
```

也可以组合或调整：

```text
用B的生活感，加一点D的搞怪，别太像广告。
```

如果你已经有方向，或者希望直接交稿：

```text
写一条搞怪口播，主角是来面试的一次性刷头，30秒。
```

```text
方向你来定，直接写一条单人可拍的30秒脚本，不用让我选。
```

明确指定方向、选择已有方案或授权代选后，技能直接展开，不重复确认。只改一句台词或一个镜头时，也不会重新走完整选题流程。

选多个编号（例如“DE”“D+E”）默认将两种风格融合成**一条脚本**，先说明各自作用，再写统一故事；不是自动生成两条成片。只有明确说“D、E各写一条，分别成片”或原任务已有多稿约定时，才拆成多条。

## 同一商品可以拍成什么

| 内容方向 | 观众为什么看 | 创意可以从哪里来 |
|---|---|---|
| 产品展示 | 看操作、细节、质感与变化 | 物件编舞、微距揭示、动作接力、匹配转场 |
| 生活种草 | 代入一个具体生活时刻 | 日常仪式、小发现、真实取舍、情绪余韵 |
| 人物口播 | 听一个有态度的人讲明白或讲好笑 | 选购观点、吐槽、自问自答、角色独白 |
| 搞怪离谱 | 看荒诞设定怎么升级和收尾 | 拟人、身份错位、过度认真、冷幽默 |
| 剧情反转 | 跟人物一起误会，再重新理解 | 目标错位、对话歧义、视角揭示、伏笔回收 |
| 感官氛围 / ASMR | 享受声音、动作和秩序 | 材质、开合、排列、节奏与构图 |
| 伪纪录 / 采访 | 看熟悉的严肃形式讲意外的事 | 物件采访、虚构职场、生活观察栏目 |

“口播”是形式，“桌面物品召开述职会”才是具体点子。多个方向需要在观看动机、视角、冲突、关键动作或观看回报上有区别，不能只换标题和开场措辞。

搞怪可以大胆，商品事实要准确。明显的拟人属于演绎；杀菌率、承重、价格、库存或真实买家经历不能靠剧情补出来。

## 它怎么工作

```text
商品资料与使用场景
        ↓
梳理商品事实、观众处境与本条目标
        ↓
给出不同创意 → 解释取舍 → 用户选择或组合
        ↓
展开分镜、台词、声音与拍摄说明
        ↓
按内容类型审稿，标记待核实事项
        ↓
保存脚本与创意机制 → 有反馈后复盘更新
```

1. **接任务**：读取已有资料与项目资产，提炼观众处境、商品特点、目标和制作限制。可假设的条件注明后继续，真实性相关信息不能猜。
2. **找表达**：从生活细节、商品动作、人物态度与类型机制出发，找到值得看的一幕。
3. **选方向**：给具体候选和推荐，用户可以选、混合或换一批。已指定方向或授权代选时直接推进。
4. **写成稿**：落实到时间段、动作、台词、字幕、声音与镜头目的，说明关键道具和替代拍法。
5. **分类型审稿**：搞怪看铺垫与回收，种草看体验，口播看观点与语气，展示看视觉变化。
6. **沉淀并修正**：完整策划默认保存到当前项目；有实际拍摄和上线反馈后，更新机制的适用条件与验证状态。

详细交互分支见 [方向选择能力卡](ecommerce-video-director/references/direction-selection.md)。

## 你会拿到什么

| 你提出的任务 | 对应交付 |
|---|---|
| “不知道拍什么” | 有编号的创意选项、推荐理由与制作取舍 |
| “选这个，写成脚本” | 创作依据、完整分镜、台词、拍摄要点与自检 |
| “只改第二镜” | 指定范围的改稿、修改目的与必要衔接 |
| “拆一下这个参考视频” | 可观察的声画结构、机制推断、可迁移条件和来源 |
| “把这条沉淀下来” | 有来源、版本、标签、适用边界和验证状态的资产 |
| “上线后为什么表现不同” | 观察、原因假设、比较限制与下一轮内容测试问题 |

完整策划默认保存 Markdown，不强制生成 HTML、PDF 或视频。只有创意咨询、局部改稿时，默认在对话中交付；用户指定的格式和目录优先。

稿件会区分 **创意草案、待核实、可拍摄稿**。待核实的关键事实或尚未完成的关键测试，不会被藏进“可直接发布”的台词里。

## 示例：从商品到创意选择

以下为虚构演练，不代表真实商品规格、消费者经历或已验证效果。暂按可更换刷头的一次性马桶刷设计，实际操作要对照SKU资料。

**输入**：“一次性马桶刷，帮我写短视频。”

| 选项 | 方向 | 一句话点子 |
|---|---|---|
| A《任务接力》 | 展示 | 安装、刷洗、卸下按动作节奏衔接成一段接力 |
| B《清洁结束以后》 | 种草 | 从打扫后的工具收尾，拍到人终于回到自己的生活 |
| C《工具也有收尾成本》 | 口播 | 从“用完怎么办”切入，讲一个具体选购观点 |
| D《保洁面试》 | 搞怪 | 刷头参加面试，工作宣言是“干完就走” |
| E《你怎么刚来就走》 | 剧情 | 开头像在追问离职同事，拉开画面才发现是在对刷头说话 |

实际交付会进一步补开场、关键动作和制作难度，再让用户选择。用户选E后，才展开E的完整时间线与台词。

想看完整脚本颗粒度，可以读 [同一商品的五方向练习](ecommerce-video-director/references/worked-example.md)。示例用于解释方法，不是以后所有商品都要套用的情节。

### 跨品类创作记录

新增 [examples/](ecommerce-video-director/examples/README.md) 保存完整的输入、候选、选择过程、实际脚本、评审与未验证项。目前包含粘毛器、挂耳咖啡、双向拉链外套三个固定任务的创作演练，分别使用尺度揭示、生活声画和选购观点，不把所有商品都套成面试或辞职。

每条会注明希望观众记住的具体特点、对应镜号与选择理由。示例资料是合成条件，方向由作者为演练指定，未进行样品、观众或上线验证；本次实际输出和自查范围见 [演练记录](ecommerce-video-director/evals/creative-exercises.md)。真实品牌交付不自动公开到示例库。

另附 [D搞怪＋E剧情反转的融合示例](ecommerce-video-director/examples/04-style-fusion.md)，根据用户对“选DE应该合成一稿”的反馈编写，展示两种风格如何服务一个事件，而不是拆成两条广告；商品条件和效果仍未实测。

## 怎样沉淀资产

资产不只是一份“好脚本合集”，还要保留来源、适用条件和结论的可信程度。

| 资产类型 | 保存内容 | 复用前检查 |
|---|---|---|
| 产品事实 `fact` | 准确主张、SKU、来源、条件、有效期 | 是否仍适用于本次商品和时间 |
| 脚本 `script` | 创意方向、概念、分镜、版本与引用 | 是否与本次目标和资源匹配 |
| 创意机制 `pattern` | 为什么成立、最强场面、可替换部分与边界 | 换商品后是否成立，需要什么事实支撑 |
| 复盘 `review` | 数据来源、观察窗口、样本、假设与下一次测试 | 条件是否可比，结论有没有超出数据 |

没有上线数据也能记录创意，但状态是“待验证”。播放高、已拍摄、主观喜欢，都不能自动升级成普适的成功公式。新版本保留历史；品牌私有事实与素材不会自动跨品牌迁移。

新项目可使用以下本地结构；已有资产格式优先，不强制迁移：

```text
你的项目/
├── outputs/<项目标识>/<脚本ID>-v01.md
└── content-assets/<品牌标识>/records/<资产ID>/v0001.json
```

### 可选的本地工具

在仓库根目录运行以下示例。保存命令使用随包的虚构示例，不代表真实品牌资产：

```bash
# 保存示例记录；再次保存同一ID时创建新版本
python3 ecommerce-video-director/scripts/asset_store.py --root ./content-assets add \
  --input ecommerce-video-director/assets/script-record.example.json

# 按品牌与标签搜索最新版本
python3 ecommerce-video-director/scripts/asset_store.py --root ./content-assets search \
  --brand demo --tag 搞怪

# 输出即时计算的索引
python3 ecommerce-video-director/scripts/asset_store.py --root ./content-assets index --brand demo

# 检查记录结构、时间线和引用
python3 ecommerce-video-director/scripts/asset_store.py --root ./content-assets check
```

保存命令返回实际路径和版本号；检查成功返回 `ok: true`。字段缺失、镜头时间不连续或关联资产不存在时，工具报错并以非零状态退出。校验范围不包括事实真伪和创意效果。

字段、状态与工具边界见 [资产工作流](ecommerce-video-director/references/asset-workflow.md)。实际项目的 `outputs/` 和 `content-assets/` 默认被 Git 忽略，不随本仓库上传。

## 使用边界与验证状态

技能用于电商短视频策划、脚本、分镜、改稿和内容资产工作；不操作投放账户，不代替完整影视编剧，也不会仅凭脚本请求自动生成、发布或投放成片。

商品功效、对比、价格、库存、认证与用户见证必须有来源。演绎与特效不冒充实测。最新平台规则需要按任务核验，不承诺审核通过、播放量或成交结果。

工具测试覆盖版本保留、品牌隔离、引用、路径和镜头时间等行为。运行方式：

```bash
python3 -m unittest discover -s ecommerce-video-director/scripts -p 'test_*.py' -v
```

`evals/scenarios.json` 另列出了选方向、续写、代选、改稿和事实边界等验收预期。它们不等于已经完成的独立模型盲测；工具测试也不证明创意有效，仍需实际使用、试拍与上线反馈。
